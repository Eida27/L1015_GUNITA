# ADR 011: Explicit database integrity and least privilege

Accepted for Phase 1. SQL files in `src/server/db/migrations` are authoritative; Drizzle provides typed schema/query integration and proposal generation only. Never use destructive schema push or automatic down migrations. The migration runner serializes with an advisory transaction lock, checks file history/checksums and a catalog fingerprint of columns/defaults, constraints, indexes, enums, triggers and non-extension functions. All pending migrations and ledger writes share one transaction. Unexpected SQL or catalog drift requires explicit operator review, not a ledger edit.

`gunita` is the local bootstrap account; `gunita_migrator` owns application objects, has no superuser/createdb/createrole/bypass privileges, and is used only by operator commands. `gunita_app` is the web runtime: domain CRUD, constrained profile columns, read-only static geometry/quota, insert/read-only audits, no schema creation/DDL or role promotion. The publication trigger owns quota writes using a tightly scoped security-definer function and schema-qualified ledger references. Profile identities and thought publication identity/location/30-day UTC duration are immutable in SQL. Only the future verified operator bootstrap command may promote roles.

Local `db:prepare` upgrades Phase 0 configuration without rotating the existing database password or deleting data: `.env` holds the runtime URL; ignored `.env.db` holds separate bootstrap/migration URLs and a recoverable copy of the runtime URL. Normal web launchers never load `.env.db`. Local Compose still needs its bootstrap password to initialize PostgreSQL; production must inject only runtime secrets into web and isolate operator/backup secrets (deployment phase). Existing privileged roles are rejected. The current tools intentionally do not attempt password rotation or auto-repair drift.

Better Auth `auth@1.7.11` generated the UUID user/session/account/verification schema using `scripts/auth-schema.config.ts`; raw output is retained at `docs/verification/auth-schema-1.7.11.ts.txt`. Reviewed adaptations are supported `timestamptz` date columns, a case-insensitive email index, and token/session expiry indexes. Required library fields (including internal name, optional image/IP/user-agent) remain intact. Phase 2 must generate the mandatory internal name/pseudonym server-side, create the private profile atomically, prevent client role/name/pseudonym injection, and disable unnecessary session IP/user-agent storage. Auth routes/configuration are not implemented in this phase.

Post creation automatically records a privacy-minimized quota event and serializes per account in a database trigger; five events in the previous 24 hours block a sixth creation, including deleted posts. Events have no thought FK and survive content deletion; account deletion cascades them. Later posting services **must not insert an additional quota event**. The trigger is defense in depth; Phase 5 still checks verified/active/consented membership and translates the quota error safely.

Review fix: advisory locking does not refresh a fixed transaction snapshot. Migration 0005 therefore requires **READ COMMITTED** for publication and rejects REPEATABLE READ, SERIALIZABLE and READ UNCOMMITTED with SQLSTATE `25000` before quota work. The entire failed insert rolls back without a thought/event; callers must roll back explicit transactions and must not silently switch isolation in an error handler. This is the supported publication contract for Phase 5. The original four migration files/checksums remain unchanged. Six pre-established REPEATABLE READ snapshots reproduced six commits before the fix; unsupported-mode regressions now assert six safe rejections/zero rows, while the READ COMMITTED race still commits five of six.

Public data access uses an allowlist and the shared active-published predicate, with `statement_timestamp()` so time advances between queries even in a long transaction. It exposes only pseudonym, public ID, text/emotion, coarse point/label and publication/expiry times. No counts, owner ID, role/status or email are included. Permission guards belong in later route/services. Maintenance owns its transaction, deletes expired thoughts and cascading interactions in bounded batches, and purges expired sessions/tokens/rate buckets, quota older than 25 hours and audit older than 90 days. The extra quota hour is cleanup allowance; quota reads use the exact rolling 24 hours. Scheduler/whole-job concurrency and draining all batches are Phase 5 work.

Admin audit is structured, without free-form body/email/IP/coordinate fields. Foreign keys clear subject/admin links on deletion; update triggers permit identifier erasure but reject changing history. Runtime cannot update or delete audits. Retention maintenance uses restricted operator credentials for now; production maintenance-secret isolation is later work.

PostgreSQL statement, parameter, duration and error-context logging is disabled in Compose. Errors returned by operator CLIs are generic, since node-postgres error objects can include SQL/detail values. Preserve these settings with future diagnostics: neither original picked coordinates nor user bodies belong in logs.
