# ADR 016: loaded edit preconditions and actionable report discovery

Status: implemented and approved by the single [scoped re-review](../verification/reviews/final-rereview.md) at source `e4eb30ab1424fcb4f36fc27aad2f7ed02ecfad37`, accepted by the controller on 2026-10-29. FBR-I01/I02 are addressed with no new findings; subsequent evidence-only commits do not change the reviewed implementation. Authority: specification stale-edit 409 contract and [controller Ruling 10](../verification/rulings.md). Public launch/integration remain separate authorization and operational gates.

An account/row lock serializes writes but cannot identify a draft loaded before another save. `GET /api/thoughts/:publicId/edit` now freshly authorizes the verified active owner, locks the unexpired row, and returns only `{body, emotion, version}` for published thoughts, with `private, no-store`. After any row-lock wait, a fresh database statement rechecks published/unexpired visibility before disclosure. Hidden targets remain unavailable to this new read, consistent with the existing viewer/dashboard contract. The public DTO and viewer DTO gain no revision or identity fields.

The opaque quoted version is an HMAC over public ID, the exact PostgreSQL `updated_at` text, body and emotion. These inputs come from the same locked row. PostgreSQL microseconds never pass through a JavaScript Date for versioning. `PATCH` keeps its body/emotion-only JSON contract and requires the snapshot's `If-Match` header. After fresh authorization and the row lock, missing, invalid or stale preconditions yield safe `STALE_EDIT` 409 without rate-counter/content changes. Successful writes monotonically advance `updated_at` by at least one microsecond, including identical edits and a backwards wall-clock adjustment. Expiry is rechecked in the update; immutable publication fields and quota ledger remain unchanged. No migration, applied-checksum change or role grant is required.

Edit loads the private body/emotion/version together, including when the public representation was older. It never fetches a new version immediately before submitting an old draft. Conflict keeps both inputs, disables another stale save and offers an explicit localized action to replace the draft with the saved snapshot. Cancel and viewer lifecycle invalidation retain their existing behavior. A reload intentionally discards the draft only on the user's labeled action; automatic merge is outside this scope.

The moderation queue defaults to `view=actionable` (open plus reviewing); explicit open, reviewing, resolved and all views remain available. All views use ascending `(created_at, id)` order. A versioned base64url cursor contains that view, the last audited report ID and a UTC timestamp with all six PostgreSQL fractional digits. The server validates the cursor shape and rejects a view mismatch. The cursor is navigation data, not authorization: every read still freshly authorizes an administrator and audits each disclosed row in the same transaction. Expired targets remain excluded from every view, including resolved history.

Changing views clears rows, cursor and mounted action selections. Refresh and successful moderation return to the first page, so resolved items disappear from the actionable view. This is live keyset traversal, not a frozen historical snapshot: newly actionable older rows are found on Refresh. Reports are never automatically hidden or prioritized by report volume.

Costs: old private queue cursors are incompatible and must be discarded; old clients without `If-Match` fail safely and must reload the new artifact. HMAC key rotation also invalidates an outstanding edit snapshot safely. The selected oldest-first policy may need later staffing review. No notification, assignment, identity retention or public-discovery contract was added. See [actual validation and remaining gates](../verification/final-fix.md).
