# MVP acceptance matrix

The 32 IDs/scenarios/expectations below come verbatim from the approved plan. Results mean **local executed acceptance**, not public deployment/provider certification. Evidence combines retained executed receipts with Phase 10's current unfiltered run; test presence alone is not a pass. The command/environment register in [tests](tests.md) gives exact commands and outcomes. Current code pointers are repository-relative; the linked phase reports explain assertion scope and historical failures.

`F10` = the Phase 10 current full-suite receipt in [phase-10.md](phase-10.md); its five new literal cases use a new random real PostGIS DB, actual Better Auth/password/session guards and least-privilege runtime. Only mail transport is stubbed in those cases; actual SMTP/reset coverage is retained separately. `B` = controller normal Browser [ledger](browser-acceptance.md) and [final 7/8 receipt](phase-8-browser-receipt.md). `E8` = Phase 8's distributed standalone E2 E proof, accurately [attributed](phase-8.md). `O9` = actual Docker/TLS/restore/maintenance [rehearsal](phase-9.md). All earlier default test runs used host Node 24.19.0/pnpm 11.25; F10 uses host 24.22.1; O9 images remain pinned 24.19.0. PostgreSQL 17.11/PostGIS 3.6.4 throughout the current gates.
