Exact existing Better Auth, separate adapter, Drizzle and generated UUID/timestamptz schema are preserved. Added exact nodemailer **10.1.7** and @types/nodemailer **8.0.2** after current registry verification.

`src/server/auth/library.ts` configures the pinned library, library Node scrypt (N=16384, r=16, p=1), verified login, seven-day signed HttpOnly/Lax cookies (Secure for HTTPS), one-hour reset/verification, all-session reset revocation, no cookie session cache, no raw IP/user-agent retention, no library logs and no account-change/delete endpoints. The library handler is never exported.

Migration **0006_account_identity.sql** creates the default member/active profile and random permanent pseudonym atomically with each inserted user; the required internal name is overwritten server-side and image cleared. Pseudonym suffix has 90 random bits from a truncated UUIDv4; actual unique collisions retry up to eight times before rolling back. Existing SQL files/checksums and profile immutability remain intact. Low-level Phase 1 fixtures remove the auto-created profile only when explicitly constructing profile-integrity fixtures; the auth suite tests automatic creation under the actual runtime role.

Every lifecycle operation constructs Drizzle/Better Auth on one acquired PoolClient and owns the outer transaction. Adapter `transaction:false` deliberately defers to that existing boundary; it is not a claim that the adapter's default is atomic. Fresh state locks, verification claims, passwords, session revocation and cascades share the actual connection. COMMIT reporting ROLLBACK fails. Forced DB failure proves token/session/password writes roll back together. Signup races serialize by normalized-email transaction advisory lock. Read [ADR 013](../adr/013-account-lifecycle.md) for decisions and tradeoffs.

## Producer interfaces and routes

- `getAuthService()` in `src/server/auth/runtime.ts` lazily reads runtime-only configuration and owns a max-four-connection pool. Never import this module from clients.
- `getAuthService().withAuthTransaction(async context => { ... })` supplies `{client,auth}` on one outer transaction. Call guards and perform the protected write through this context; never release its lock and write using another pool connection.
- Guards in `src/server/auth/guards.ts`: `requireAuthenticated(context,headers)`, `requireVerifiedMember(context,headers)`, `requireAdmin(context,headers)`, `requireOwner(context,headers,ownerId)`, and `requireActiveAccount(actor)`. They freshly check DB session expiry, current verification, profile existence/status and role/owner, holding user/profile/session row locks. Actor `{userId,email,emailVerified,pseudonym,role,status}` is private internal data, never a public DTO. New mutation routes must additionally validate Origin, bounded input, their own limits and current posting consent.
- Public auth POST allowlist: `/api/auth/sign-up/email` `{email,password}`; `/sign-in/email` same; `/send-verification-email` and `/request-password-reset` `{email}`; `/verify-email` `{token}`; `/reset-password` `{token,newPassword}`; `/sign-out` `{}`. All callbacks/return destinations are fixed, all hostile identity/role/verification/image fields are stripped. Success is `{status:true}`; token/user/session JSON is never returned. All responses disable caching.
- `GET /api/me/account` returns only private `{email,emailVerified,pseudonym}` for an active verified member, with `Cache-Control: private, no-store`. `DELETE` on the same route requires `{password}`, same Origin and current verified/active state; verifies the current library hash immediately before deleting, clears matching verification data and atomically cascades all sessions/content.
- Every other default library path is unavailable, including `get-session`, update-user, change-email/password, delete-user/callback, social/OAuth and default reset callbacks. Only application handlers are exported from the Next route files. Query-token variants are rejected.
- Durable auth limits use existing `rate_limit_counters` before lifecycle BEGIN so failed credentials cannot roll back a counter. HMAC normalized email/token or extracted library session cookie, never the entire arbitrary cookie header. Limits are 10 login attempts / 5 other attempts per fixed 15-minute key window, plus 120 direct-client requests per action/minute. Forwarding headers are ignored; no raw IP is retained. Existing cleanup removes expired buckets. Restricted trusted proxies, production Turnstile and broader abuse policy remain Phase 7.
- `src/server/auth/email.ts` is provider-neutral `{check,send}` with local SMTP/Mailpit. SMTP health is checked for every signup/reset/resend address before existence lookup. Total outage produces identical 503 for known/unknown/duplicate addresses. A post-preflight recipient failure returns the same conditional 200 receipt while rolling back writes; receipt never guarantees account creation or email delivery. Public resend deliberately excludes the caller's session so another signed-in account cannot turn library EMAIL_MISMATCH into an enumeration signal. No constant-time SMTP/network claim is made.
- Verification uses the library JWT signer with a nonce and a one-use stored digest bound to the account. Reset uses library token generation/consumption. Both expire after one hour. Email URLs use fragments, immediately removed on client hydration, and no token goes in an HTTP query, redirect, storage or log. Forms explicitly use POST and disabled submit buttons before hydration; no-JavaScript tests prove native fallback cannot submit credentials in a URL.
- UI: `/sign-up`, `/log-in`, `/verify-email`, `/forgot-password`, `/reset-password`, `/log-out`, private `/settings`; errors, conditional delivery, resend, missing/expired links, logout/deletion success, readonly identity and current-password deletion. Policy links resolve to explicitly labeled local draft summaries. Phase 3 owns localization/age/theme refinement; no fake map or composer was added.

Publication still supports READ COMMITTED only, and later services must not duplicate trigger-owned quota events. This phase does not change the Phase 1 geometry, expiration or quota interfaces.

7. `node node_modules/vitest/vitest.mjs run tests/integration/auth.test.ts -t 'token throttle'`: **1 failed / 18 filtered**, changing unrelated cookies bypassed the token limit (400 instead of 429).
