# Phase 3 — bilingual accessible shell and first-visit warning

Phase 3 implements the approved calm shell, English/Filipino UI, preferences, adult/content warning, draft policies/help, and shared accessible states/dialog. It adds no map, thought API, sharing feature, publishing consent, provider integration or real crisis contact. Later phases remain gated. ## Producer contracts for Phases 4–6

- `PreferencesProvider` in `src/components/ui/preferences.tsx` lives in the root layout. `usePreferences()` supplies typed `t(MessageKey)`, `locale: 'en' | 'fil'`, `theme: 'system' | 'light' | 'dark'`, `ready`, `acknowledged`, and its per-provider `store`. `Text` supports localized labels from a server shell without serializing private actor objects. Catalogs are `locales/en.json` and `locales/fil.json`; `MessageKey` comes from English keys and both catalogs must have the exact same complete key set. API UI errors use allowlisted `ApiErrorCode` → `MessageKey`, never raw server text. Keep authored thought bodies, pseudonyms, email addresses and location names outside translation calls.
- Non-identifying localStorage keys: `gunita.locale` (`en`/`fil`), `gunita.theme` (`system`/`light`/`dark`), `gunita.warning` (the exact current `WARNING_VERSION`, initially `2026-10-20.1`). Default locale is the first supported browser language, otherwise English; `fil` is not replaced by `tl`. Default theme follows CSS `prefers-color-scheme`, including live system changes; explicit theme overrides it. No preference or acknowledgment cookie exists. Generic SSR is always English/system with acknowledgment false; locale/theme are applied after hydration. No DOB is collected. Selects are disabled until hydration. Blocked storage keeps preferences and an honest acknowledgment only within the current provider/visit; reload asks again.
- `PublicContentGate` in `src/components/ui/public-content-gate.tsx` is a **loading boundary**, not a visual overlay. Its only content prop is `load: PublicContentLoader`, with signature `(signal: AbortSignal) => Promise<ComponentType>`. Define a stable loader in a **client wrapper**, then pass that wrapper to a generic server page. Never pass server children, a pre-started Promise, fetched thought data or authored text from server HTML/RSC/metadata. The initial root uses a no-op client loader because Phase 4 owns the map. No test fixture route exists in the app.
- The loader is invoked only after hydration plus current-version acknowledgment. It receives an AbortSignal; cleanup aborts on gate unmount/revocation. Its result and error paths re-check both signal and current storage before rendering. The new warning mounts with an unchecked checkbox every time. Storage/focus/pageshow events revalidate acknowledgment; a 500ms provider interval also detects same-document storage clearing (which emits no native storage event). Fetch permission is re-read immediately before loader start/completion; unauthorized SSR never invokes it. This is UX self-attestation, not authorization of otherwise public APIs or robust age verification.
- Example for later map/share client wrappers: a module-level loader `async (signal) => { const { Map } = await import('./map'); return () => <Map signal={signal} />; }`. Start public thought/map fetches only inside that loader or its mounted component; pass the signal through **every** fetch and re-check `usePreferences().store.isAcknowledged()` immediately before subsequent event-driven requests. No top-level side-effect fetch, server/RSC fetch, UGC prefetch or sensitive metadata is allowed. Keep the loader stable, and key a wrapper by public ID when changing shared thoughts so the old loader unmounts/aborts. A hidden/blurred server child is explicitly forbidden. Phase 4/5 tests must exercise their actual routes/data as they are added; Phase 3 proves this actual boundary with isolated browser-network sentinels.
- `Dialog({titleId,descriptionId?,onClose?,children})` uses native modal/inert semantics, title focus, explicit forward/backward Tab wrap, Escape dismissal only when `onClose` exists, and trigger focus restoration (or `main#main` fallback). Title/description IDs must be unique. Render only while open, use client content, and supply a close callback for dismissible map/detail/composer dialogs. On phones it is a scrollable bottom sheet; desktop uses a centered dialog. The age warning supplies no close callback. Both app main landmarks have `tabIndex=-1` for skip/fallback focus.
- `LoadingState`, `EmptyState` and `ErrorState({retry?})` in `states.tsx` provide localized status/alert semantics, a static skeleton and safe retry. `error.tsx` uses the installed Next 16.4.2 **retry** prop; `not-found.tsx` supplies a localized generic fallback. No exception contents are displayed.

## Controller Browser finding and final repair

The controller's fresh normal Browser tab on the first standalone showed the mandatory warning with unchecked checkbox and disabled entry. Targeting the warning heading with Escape closed the native dialog (`open=false`, active BODY) without attestation. The loading gate remained unacknowledged, but the warning UI was stranded. The existing Playwright page-keyboard Escape check and a heading-keyboard diagnostic did not reproduce that browser-specific cancellation path; neither was used to dismiss the controller's finding.

A new actual-app regression explicitly exercises heading Escape/Tab focus, then reproduces the observed native closed state using `HTMLDialogElement.close()`. RED command `node node_modules/@playwright/test/cli.js test tests/e2e/shell.spec.ts -g 'mandatory warning survives'`: **1 failed / 6.9s**, `getByRole('dialog')` missing after native close. The shared primitive now sets native `closedby=none` for mandatory dialogs, prevents Escape in capture phase, and reopens a still-mounted mandatory dialog on an unexpected native close event. Dismissible dialogs retain `closedby=closerequest`, Escape callback and trigger focus restoration. The acknowledged warning still unmounts normally.

The first post-pause full standalone E2E run was **12 passed / 4 failed**, not a pass. Three isolated loading-harness cases failed before React startup because Vite's whole-`process.env` definition did not replace CommonJS React environment reads. The corrected test host prefixes only literal `globalThis.process = { env: { NODE_ENV: "production" } };`; it never serializes the runner's real environment. The exact generated browser bundle is retained in ignored `.local/phase-3-gate-harness.js` for a private-value scan. The remaining failure was a selector error: Playwright `getByText` excludes NOSCRIPT; a native no-JavaScript diagnostic proved the node was present, inline and had a nonzero visible rectangle. The test now targets `locator('noscript')` directly. No production warning gate was relaxed for either harness issue.

After the pause, the controller restored the same DB/Mailpit services and persistent volume. The first attempted launcher call omitted `LOCAL_PREVIEW=true`, and the existing configuration guard correctly rejected production-only missing values. Supplying the already-approved local preview process flag started the validated loopback artifact; private env files were not modified. Subsequent gate results and controller retest are recorded in the final verification table.
