## Producer contracts

- `src/lib/thought-contract.ts` exports `PublicThought`, `graphemeCount`, and the centralized `CURRENT_GUIDELINES_VERSION = guidelines-2026-10-19`. `Intl.Segmenter` counts grapheme clusters. Without it, the conservative code-point fallback may reject complex emoji earlier, never admit over 280 graphemes. Authored HTML/Markdown-looking text remains plain escaped text.
- `createThoughtService({auth,pool,origin,secret})` uses `auth.withAuthTransaction` and the actual verified-member guard on the **same client**, with explicit READ COMMITTED isolation. Account/user/profile/session locking follows ADR013. Authorization and current consent are checked on the server, including direct API requests. The existing thought INSERT trigger alone records quota; deleted thoughts retain their creation events.
- POST `/api/thoughts`: strict `{body,emotion,location:{lat,lng}}`, canonical Origin, bounded JSON, narrow content/spam checks, current consent, and transactional server-side coarsening. Submitted precise coordinates remain transient; only the recomputed coarse point/cell/label/version reach storage. Returns 201 with allowlisted public detail.
- GET `/api/thoughts/[publicId]`: public, `no-store`, current published-only detail. DTO: `{publicId,body,emotion,pseudonym,location:{label,lat,lng},createdAt,expiresAt}`. No account/owner IDs, privacy-cell data or reaction totals. Hidden, deleted, unknown and expired IDs share the same 404 `THOUGHT_UNAVAILABLE` response.
- PATCH `/api/thoughts/[publicId]`: verified author only, strict `{body?,emotion?}`, private no-store receipt. Location, public ID, creation and 720-hour expiry stay immutable at both service and DB boundaries. Durable edit budget: 20 successes/account/hour. DELETE hard-deletes own live thought and cascades dependencies; the quota event remains. Non-owner mutations receive generic unavailable.
- GET `/api/thoughts/[publicId]/viewer`: separate private no-store verified-viewer response, `{canManage:boolean}` only. Public DTOs never carry ownership information. The current share/detail view provides owner edit/delete; the own-thought dashboard remains Phase 6.
- GET/PUT `/api/me/consent`: verified member, private no-store. PUT accepts only `{version:CURRENT_GUIDELINES_VERSION}` and records consent atomically/idempotently. New publication independently checks the stored current version. Phase 7 reuses this contract.
- Both singleton map selection and terminal-group member selection fetch full detail by `publicId` only after live acknowledgment and behind AbortSignal. Bulk/map-member DTOs remain minimal. Group Back/exact focus and Escape/trigger restoration remain; successful pagination focuses the new page's first member. Edit focuses its textarea; Cancel and successful Save return focus to Edit. The picker explicitly clears the map preview source before replacement requests, including rejected replacements. A safe preview selected during asynchronous style/land loading is queued until the source exists, and the latest safe state is reconciled when the engine becomes available. A raw pick stays only in the mounted map's transient ref; it never enters URLs or storage.
- `/thought/[publicId]` SSR/RSC/metadata remain generic and `noindex`; no authored body or pseudonym is fetched before the client acknowledgment boundary. Generic HTML shell uses HTTP 200; actual unavailable detail API uses 404. Generic social metadata never copies authored content.
- Map refreshes every 30 seconds while mounted and refreshes immediately after own publication. Detail reads are uncached, so deletion/hiding cannot be resurrected by detail caches. This is a local discoverability mechanism, not a realtime or production SLA.

## Maintenance handoff to Phase 9 packaging

`pnpm maintenance:run` launches dedicated `scripts/maintenance.mjs`: immediately drain, then schedule each hour. `--once` performs one run and exits. `pnpm maintenance:expire` now also drains. The web server never starts this process or receives its operator credentials.

Provide only the maintenance process `MIGRATION_DATABASE_URL` (plus local `.env.db` loading for local operation). Existing runtime grants deliberately cannot delete quota/audit retention rows; no web grants were widened. Phase 9 must package this command as an independently supervised service, with restart policy, health/lag monitoring and graceful SIGTERM/SIGINT stop. Stop clears the timer and allows the current batch/job to finish, closing its dedicated connection. No production Compose wiring is claimed here.

`runMaintenance(client,{batchSize})` takes session advisory lock `(196742,5)` with `pg_try_advisory_lock`, returns `{skipped:true}` for another owner, and holds it across existing cleanup's per-batch transactions. It drains until every table reports zero; returns `{skipped:false,totals}`. `finally` releases the lock after success/failure. Connection closure also releases PostgreSQL session locks. Existing visibility predicates exclude expired content before any scheduled job runs. Actual DB tests cover a competing client, rollback/lock release after a runtime-permission failure, more expired rows than a one-row batch, dependent cascades and repeat-zero idempotence.

The initial content policy and known limits are in [phase-5-content-policy.md](phase-5-content-policy.md). Production safety/legal/localization/geographic review and Phase 7 moderation remain separate gates.
