## Contracts for the next phase

- Public `PublicThought` adds exactly `reactionTypes: ['love','sad','care','happy']`. Public detail/map/HTML/metadata never contain counts, participant identities, ownership or private selections. The existing seven content/location/time fields remain allowlisted and normalized by the shared strict Zod schema.
- Existing `GET /api/thoughts/:publicId/viewer` extends its private response to `{canManage,myReaction,bookmarked}`. `canManage` retains owner-only management semantics. A current verified, active viewer receives only their own selection/bookmark; unavailable targets disclose neither. All private responses/errors are uncached.
- `PUT /api/thoughts/:publicId/reaction` accepts strict `{type}`. A different type changes the single row, the same type removes it; `DELETE` removes only the caller's reaction. Bookmark `PUT` is idempotent and `DELETE` removes only the caller's bookmark. Empty mutation inputs accept an absent body or strict `{}`. Success is the reviewed strict `{status:true}` receipt.
- Interaction mutations validate canonical Origin, bounded JSON and live verified/active account state inside `auth.withAuthTransaction`, using the actual connection and explicit READ COMMITTED. Account locks precede thought locks. The service rejects self-interaction, requires published/unexpired targets, serializes toggle/change/removal, and rechecks statement-time eligibility before and after writes. Any boundary crossed during the transaction rolls back its interaction and success counter.
- Existing database primary keys enforce one reaction and unique bookmark per account/thought. Existing foreign-key cascades and maintenance remove dependencies on hard deletion/expiry. No schema or grant changes were needed.
- A durable combined interaction budget permits 60 successes per account per fixed hour. HMAC keys use the actual runtime secret; rejection rolls back excess writes. Account guards and locks remain the Phase 2 producers; no new auth/session/consent mechanism exists.
- `GET /api/me/thoughts?cursor=...` returns `{items:[{thought,status:'published',totals:{love,sad,care,happy}}],nextCursor}` for the current account only. `GET /api/me/bookmarks?cursor=...` returns `{items:[PublicThought],nextCursor}` for current published bookmarked thoughts only. Both are private/no-store, strict input/output validated, keyset-paginated by public ID, 20 results maximum with a 21st internal continuation row. Unknown/duplicate query parameters are rejected; no account/author parameter is accepted.
- `GET /api/me/thoughts/:publicId/reactions` returns exactly `{totals:{love,sad,care,happy}}` only for the current verified/active author or an authorized admin, never member identities. Unknown, hidden, deleted and expired targets are generic unavailable, including for admins. It uses `Cache-Control: private, no-store` for successes and failures.
- Controller ruling 6 resolves the optional hidden-post dashboard ambiguity in favor of the concrete published visibility predicate: both own-thought lists and all totals endpoints exclude hidden thoughts. Phase 7 may inspect nonexpired hidden targets within protected moderation scope without widening counts.
- `/dashboard/thoughts` and `/dashboard/bookmarks` use generic noindex shells, the existing acknowledgment loader and private client fetches. Own cards expose expiration, totals and existing author edit/delete; bookmark cards expose private interaction controls. No server-rendered UGC/totals, private archive, public feed/search/profile/ranking or browser storage of private data is added. Settings/security remain the existing account flow with dashboard navigation added.
- Four localized controls expose types only publicly and own pressed state privately. Guest actions show sign-in/create-account links. Author controls cannot self-react/bookmark. Viewer failures remain fail-closed while public reading survives. Existing Cancel/Save focus behavior is preserved; successful dashboard removal focuses its heading. Private state clears on visibility/focus/page restoration, sign-in/out still use document navigation, and mounted content expires at its original deadline.
- The existing nine-emotion map filter and map-scoped accessible listing remain intact. Browser verification checks the same emotion in map requests and the rendered listing, including an empty category. Coarsening, quotas, immutable location/lifetime and maintenance are unchanged.

All new DTO TypeScript types derive from actual shared Zod schemas. Validation happens at server JSON and client consumption boundaries. A malformed producer becomes generic private HTTP 500 without payload/diagnostics; client-invalid inputs remain generic 422.
